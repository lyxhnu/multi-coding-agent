## 1. 背景与范围

### 1.1 已确认的问题

前一轮代码审查使用本地假模型和临时测试复现了以下问题。已有相关测试基线为 4 个文件、32 个测试通过；这不是本 Spec 实施后的测试结果。临时复现文件已移除，实施时必须建立永久回归测试。

| 问题 ID | 问题 | 影响 |
| --- | --- | --- |
| P01 | split-turn 压缩在历史待压缩区为空时忽略 `previousSummary` | 旧目标、约束和进度可能从后续上下文中消失 |
| P02 | 预算 guard 只使用上一条 assistant 的 usage | 刚返回的工具结果等新增内容未计入下一次请求判定 |
| P03 | `writeSessionNote()` 不经过记忆安全过滤 | 不安全笔记可以落盘、被搜索，并进入后续记忆处理 |
| P04 | 撤销只影响搜索，`memory_get` 直接读取原文 | 被撤销条目会通过直接读取重新进入上下文 |
| P05 | autoDream 取笔记第一行，而自动笔记第一行是日期标题 | 归档成功但没有提炼正文事实 |

另外两项改进属于本次明确范围：

- P06：两阶段压缩按覆盖范围复用预摘要，第二阶段不重复发送已覆盖原文。
- P07：shake 后通过原始 session entry 回读内容，不要求重新执行原工具。

### 1.2 目标

- 压缩前后有确定的信息传递关系，失败不能替换已有有效上下文。
- 每个待发送的模型请求使用一致的预算口径。
- 记忆写入、读取、搜索、归档、向量索引和撤销形成闭合的数据路径。
- 长期记忆保存正文中的有效事实，并保留来源。
- 预摘要和历史引用可验证，恢复会话后不错误复用或失效。
- 关键判断可通过现有 CLI/RPC 和 trace 验证。

### 1.3 非目标与边界

- 保留 Markdown 记忆和 JSONL 会话，不新增数据库、外部存储服务、RAG 框架或独立界面。
- 不新增 bash 工具；只新增本 Spec 定义的只读 `history_get`。
- 不增加全局记忆自动写入，不改变 `memory.enabled` 与记忆工具激活之间的现有关系。
- 不额外增加会话结束等自动记忆触发点；沿用当前手动和自动入口。
- 不引入兼容分支、旧新接口双写或双套压缩算法。接口变化同步更新全部调用方、测试与文档。
- 不自动删除或改写用户已有原始会话、trace 和记忆文件以“清理历史”。
- 撤销意味着记忆系统不再召回条目，不意味着从所有历史对话中物理擦除该事实。
- 安全过滤保证已定义检测规则的统一执行，不宣称可以识别所有形式的秘密。
- token 预算是可解释的估算，不宣称字符估算等同于所有 provider 的真实 tokenizer。

## 2. 术语与系统不变量

| 术语 | 定义 |
| --- | --- |
| 原始记录 | JSONL/Markdown 中实际保存的内容，不因上下文裁剪而原地改写 |
| 有效记忆视图 | 经解析、撤销检查、安全检查后，允许参与读取、搜索、提炼和索引的条目集合 |
| 压缩边界 | 最新 compaction entry 及其 `firstKeptEntryId` |
| 笔记快照 | 一次成功压缩对应的独立 session note，具有稳定来源标识 |
| 覆盖范围 | 某个预摘要已经处理过的连续上下文 entry 范围 |
| 请求快照 | 完成消息转换并确定 system prompt、tools、model 和输出参数后的待发送上下文 |
| 处理水位 | 已成功处理的笔记快照 ID 和内容指纹集合，不等同于扫描过的文件列表 |

| 不变量 ID | 约束 |
| --- | --- |
| I01 | 新摘要必须继承仍有效的旧摘要信息；split-turn 不能成为例外 |
| I02 | 只有有效摘要生成完成后，才能提交新压缩边界并替换当前上下文 |
| I03 | 预算判定对象必须与即将交给 provider 的请求快照一致 |
| I04 | 因上下文不足停止运行，不等于任务完成 |
| I05 | 所有记忆写入入口执行相同安全检查；外部记忆处理服务不能绕过有效视图 |
| I06 | 搜索、直接读取和向量候选不能重新返回已撤销条目 |
| I07 | 归档成功必须对应可验证的处理结果；失败不能推进水位 |
| I08 | 未成功归档的笔记不能先进行有损老化裁剪 |
| I09 | 预摘要只有在来源范围仍有效时可复用；尾部追加不应自动使其失效 |
| I10 | 历史回读不执行原工具，也不越过会话、分支和工具权限边界 |
| I11 | 重启、分支导出及恢复不能破坏已提交状态或合法历史引用 |
| I12 | 新增诊断日志不得包含被拒绝的敏感正文或敏感值前缀 |

## 3. 功能需求

### R01. 压缩摘要继承与提交

主要修改：[compaction.ts](../../src/core/compaction/compaction.ts)、[agent-session.ts](../../src/core/agent-session.ts)。

#### R01.1 数据关系

```text
上一轮有效摘要 + 本轮需要压缩的新增内容 → 新摘要
新摘要 + 保留的最近消息 → 新上下文
```

- `previousSummary` 是独立输入，不得由 `messagesToSummarize.length` 决定是否保留。
- 普通压缩和 split-turn 使用相同的摘要继承规则。
- 只有 turn prefix 需要压缩时，最终结果必须包含旧摘要与新前缀摘要。
- 没有新增内容时不重新生成或清空已有摘要；该操作是无新提交的空操作。
- 继续累计已有的文件操作记录，不拆散保留区中的工具调用和工具结果。

#### R01.2 提交顺序

1. 从当前分支计算准备数据和来源边界。
2. 校验摘要请求本身的预算。
3. 生成完整、非空摘要。
4. 确认操作未取消，来源边界仍可用于当前提交。
5. 写入 compaction entry。
6. 使用已提交 entry 重建上下文。
7. 发出完成事件。

摘要为空、响应为 `length`、error、abort，或来源已失效时，不提交新压缩边界。不得以部分摘要替代原上下文。扩展提供的压缩结果同样必须满足边界和非空等可验证条件。

### R02. 统一发送前上下文预算

主要修改：[agent-loop.ts](../../../agent/src/agent-loop.ts)、[types.ts](../../../agent/src/types.ts)、[run-state.ts](../../../agent/src/run-state.ts)、[estimate.ts](../../../ai/src/utils/estimate.ts)、[simple-options.ts](../../../ai/src/api/simple-options.ts)、[compaction-policy.ts](../../src/core/compaction/compaction-policy.ts)。

#### R02.1 预算对象与口径

检查发生在上下文 transform、`convertToLlm` 和请求快照构造完成后、实际 provider 调用之前。必须覆盖首次 prompt、工具后续轮次、steering、follow-up 和恢复后的请求。

预算至少包含：

- system prompt 和工具定义；
- 历史消息、当前用户输入、custom message；
- 本轮新增工具结果，包括同批并行结果；
- 图片等非纯文本内容的既有估算；
- 根据模型能力、调用方请求参数及现有策略确定的目标输出预算；
- 一份共享安全余量。

定义 `I` 为估算输入量、`R` 为目标输出预留、`S` 为安全余量、`W` 为上下文窗口。空间条件为：

```text
I + R + S <= W
```

实现必须区分模型最大输出能力、请求输出上限和预检目标预留，不能混为一项。沿用现有策略参数推导，不能为了通过检查而临时把目标输出预留缩成几个 token。百分比阈值、输出空间判断和底层输出上限裁剪共用估算结果与参数来源，不叠加两份安全余量。

现有模型元数据不可判定时，不伪造精确预算或宣称窗口安全；保留调用方现有元数据处理规则，并在诊断中标明未能判定的字段。

#### R02.2 usage 锚点

- 只有 provider/model、system prompt、工具集合和被计费消息前缀仍适用时，历史 usage 才能作为锚点。
- usage 锚点之后的新增内容全部计入。
- 压缩、shake、分支变化、上下文 transform 改写或模型切换后重新验证锚点。
- 不仅凭消息时间戳或消息数量判断前缀一致。
- 没有适用 usage 时重新估算，不能把零 usage 当作零上下文。
- 不得重复计算已经包含在适用 usage 中的 system prompt 和工具定义。

#### R02.3 运行状态与续跑

```text
准备请求 → 预算判定 → 足够 → provider 请求
                   → 不足 → context_limit → 缩减并重建 → 重新判定
                                              → 无进展/额度耗尽 → 明确停止
```

- 将 `context_limit` 作为结构化运行结束原因，不伪造 assistant 消息传递控制信号。
- `AgentSession` 根据此原因执行现有 shake/compaction 调度，不能依赖本轮一定产生过 assistant 消息。
- 低层 Agent 不承担记忆存储或模型摘要编排。
- 保留现有有界缩减次数和取消约束，不增加无限重试。
- 每次缩减后重新计算预算；不得只从旧 usage 减去估算 savings 就认定通过。
- 无进展或额度耗尽时，不再发送同一超预算请求，并向 CLI/RPC 明确报告原因。
- 重建和续跑不得重复消费队列、重复持久化用户消息或重放已执行工具。
- 已正常完成的回答不得仅因为需要整理下一轮上下文而被强制续跑。
- 对新增运行结束原因，同步更新 reducer、trace、CLI/RPC 和子代理结果处理，不能误映射为 `completed`。

### R03. 统一记忆安全入口

主要修改：[memory-store.ts](../../src/core/memory/memory-store.ts)、[secret-filter.ts](../../src/core/memory/secret-filter.ts)、[embeddings.ts](../../src/core/memory/embeddings.ts)。

必须覆盖：全局追加、项目追加、session note、手动 flush、自动 flush、autoDream 生成结果。

- 所有入口在持久化之前执行统一安全判定。
- 记忆提炼和 embedding 的文档输入必须来自有效视图；不得直接读取原文绕过检查。
- 对磁盘已有内容和人工编辑内容，在读取进入模型处理路径时执行相同检查。
- 不通过删除几个字符、改写敏感值或写入部分句子来保留含义已改变的条目。
- 单条写入必须能区分成功与拒绝；批量写入继续明确报告写入数量、拒绝数量和原因码，调用方不得忽略拒绝状态。
- 原因码、计数和来源 ID 可以进入日志；候选正文和敏感值前缀不得进入新增诊断字段。
- 过滤器继续是明确规则检测，不把“通过检测”表述为内容绝对不含秘密。

### R04. 有效记忆视图与撤销

主要修改：[memory-store.ts](../../src/core/memory/memory-store.ts)、[memory-index.ts](../../src/core/memory/memory-index.ts)、[memory-get.ts](../../src/core/tools/memory-get.ts)、[memory-search.ts](../../src/core/tools/memory-search.ts)。

```text
读取文件 → 解析条目 → 检查撤销与安全状态 → 有效条目
                                               → 搜索
                                               → memory_get
                                               → 提炼与向量索引
```

- 搜索与直接读取共享该路径，不各自实现不同的过滤规则。
- `memory_get` 返回有效条目组成的内容，而不是未经处理的文件原文。
- 关键字候选和向量候选来源一致；sidecar 中残留的旧向量不能使无效条目成为候选。
- 撤销后新发起的读取和搜索必须观察到撤销结果。异步检索在返回前需要避免提交已经失效的候选。
- 撤销状态损坏时明确报错，不按“没有撤销记录”处理。
- 保留现有合法人工编辑能力，尤其是无 ID 文本和带 ID 条目混合时的正文。
- 保留全局/当前项目的搜索范围，以及现有路径和符号链接约束，不扩大访问范围。
- 原始 Markdown 不因构造有效视图而被物理清除或重写。

### R05. 正文提炼、笔记快照与归档提交

主要修改：[agent-session.ts](../../src/core/agent-session.ts)、[memory-store.ts](../../src/core/memory/memory-store.ts)、[degrade.ts](../../src/core/memory/degrade.ts)。

#### R05.1 提炼协议

替换当前取第一行标题的行为，复用现有模型调用设施提炼正文。输出使用最小结构：

```ts
interface MemoryExtraction {
  facts: Array<{
    text: string;
    sourceNoteIds: string[];
  }>;
}
```

- 使用项目现有 schema 工具验证；未知字段、空事实文本、空来源列表、非本批次来源 ID 均不得视为成功。
- 提炼对象是长期有效的事实、约定、决策和经验，不是日期标题或临时任务完成状态。
- 来源笔记是待分析数据，不是系统指令；提炼调用不获得执行工具或扩大权限的能力。
- 事实经过 R03 的输出安全检查后才能提交。
- 合法的 `facts: []` 表示成功处理但没有长期事实，与无效输出、取消和调用失败区分。
- 提炼请求必须有输入预算、输出预算、超时与取消信号。超出单次处理能力时，只选择完整、可容纳的笔记批次；未选中的笔记不推进水位，也不截断正文冒充已处理。
- 不额外增加自动运行入口，也不自动写入全局记忆。

#### R05.2 快照身份与门槛

- 每次成功的上下文压缩对应独立 note ID，记录 sessionId、来源 compaction entryId 和内容指纹。
- 同一天同一会话的多次压缩不能互相覆盖。
- 只有已提交压缩的笔记进入自动归档路径；取消或失败的压缩不得生成“成功压缩笔记”。
- 处理水位按 note ID 和内容指纹判断，不能仅记录文件名。
- 时间门槛沿用当前策略；新会话数量按不同 sessionId 计算，同一会话多次压缩只算一个会话。
- 成功处理但无事实的批次可以记录为 `processed_no_facts`，不生成空记忆条目。

#### R05.3 提交与并发

```text
选取未处理快照 → 生成与校验 → 提交事实/无事实结果 → 提交处理水位
                              → 失败/取消 → 不推进处理水位
```

- 使用项目级排他锁保护归档资格判定和提交，不使用非原子的“先检查文件、再覆盖锁文件”作为互斥保证。
- 使用稳定批次 ID 实现幂等；同一批次重试不能产生重复条目。
- 记忆内容与状态文件分别写入时，不能宣称它们天然构成原子事务。若事实已提交而水位未提交，下一次必须能识别该批次、完成状态收敛，而不是重复追加。
- 提交前重新验证来源快照；生成过程中被修改的来源不能按旧指纹推进水位。
- 生成失败、协议无效或输出被安全检查拒绝时，不提交本批次为已处理；不得把部分写入伪装成完整归档。
- 原上下文压缩提交和归档提交分别记状态。归档失败单独报告，不回滚已经成功的上下文压缩。
- 锁释放、超时和取消路径必须完整，不遗留仍在运行的提炼调用。

#### R05.4 老化顺序

- 只有成功归档或明确成功处理为无事实的笔记允许进行有损老化。
- 未处理笔记即使超过年龄阈值，也不能先截掉正文。
- 老化不得改变已处理快照的身份，导致同一来源被误判为新的待归档知识。
- 沿用现有老化层级与时间阈值，不增加新的遗忘策略。

### R06. 基于覆盖范围的两阶段压缩

主要修改：[agent-session.ts](../../src/core/agent-session.ts)、[compaction.ts](../../src/core/compaction/compaction.ts)、[session-manager.ts](../../src/core/session-manager.ts)。

预摘要必须记录以下来源信息，而不是仅记录分支长度：

```ts
interface PrefixSummaryCheckpoint {
  baseCompactionId: string | null;
  coveredStartEntryId: string;
  coveredEndEntryId: string;
  sourceFingerprint: string;
  summary: string;
}
```

- 指纹覆盖实际摘要输入，包括基础摘要和覆盖范围内的有效内容；entry 数量相同不代表内容相同。
- 按现有预触发阈值启动稳定前缀提炼，不因本次修改提高后台调用频率上限。
- 第一阶段生成“旧摘要 + 稳定前缀”的摘要；第二阶段只输入有效预摘要与尚未覆盖的内容。
- 新尾部追加不会使已覆盖前缀失效。
- 来源不再属于当前分支、基础压缩边界改变或前缀内容被改写时，不使用该预摘要。
- 没有有效 checkpoint 时，同一算法从当前有效基础摘要和未覆盖范围开始处理，不维护第二套兼容或降级实现。
- 后台结果返回时再次校验来源，不把旧分支的结果挂到新分支上。
- 仅完成并校验通过的 checkpoint 可以持久化；恢复时再次校验，不恢复半完成调用。
- 不重放已经摘要覆盖的原始前缀，不破坏原始 JSONL，不消费主运行的消息队列。
- 两阶段调用共享既有有界生命周期和费用统计；不得遗失第一阶段的 usage。

### R07. shake 历史回读

主要修改：[shake.ts](../../../agent/src/harness/compaction/shake.ts)、[session-manager.ts](../../src/core/session-manager.ts)、[history-get.ts](../../src/core/tools/history-get.ts) 及工具注册/权限入口。

#### R07.1 工具契约

```ts
interface HistoryGetInput {
  entryId: string;
  blockIndex?: number;
  offset?: number;
  limit?: number;
}
```

- `entryId` 是当前会话的原始逻辑 entry ID，不是任意文件路径或 trace ID。
- `blockIndex` 定位原始内容块；同 entry 存在多个可回读块且未指定时，返回明确参数错误，不猜测目标。
- 文本分页使用一致、明确的字符单位；`offset` 为非负整数，`limit` 为正整数，返回内容不得截断 Unicode 字符。
- 实现必须定义默认页大小和硬上限，并保证内容加元数据在现有工具输出预算内；不得允许通过超大 `limit` 绕过硬上限。
- 结果携带来源 ID、块位置、分页范围和下一页位置/结束标识，调用方不必解析自然语言占位符才能继续分页。
- 返回实际保存过的内容。原始写入前已被截断的部分无法恢复，不得声称能够恢复。

#### R07.2 来源与权限

- shake 占位符提供原始 entryId、块位置和可用的回读方式。
- 只允许读取当前分支祖先链上的合法 shake 来源，包括后来被 compaction 从工作上下文移除的来源。
- 不读取其他分支、其他会话、任意路径或 trace 请求全文。
- 不执行原始工具，不重新读取原文件来冒充历史结果。
- `memory_search/memory_get` 的历史结果不得作为撤销绕过路径；拒绝返回这类旧快照，并明确要求使用当前记忆工具。
- 遵守 allowlist、denylist、Plan Mode 及子代理权限，不借新增工具扩大已有访问能力。
- 只有运行时确实提供回读能力时，占位符才能声明可调用的回读方法。
- 回读是一次新的、有界工具结果，不解除持久化 shake，不永久恢复整个历史上下文。
- 未支持的内容类型明确报告，不自动转换为重新执行原工具。

## 4. 模块责任与诊断

| 模块 | 责任 | 不承担的职责 |
| --- | --- | --- |
| `packages/ai` | 共享 token 估算、输出参数和空间计算基础 | 不编排会话压缩或长期记忆 |
| `packages/agent` | 最终请求边界检查、结构化运行原因、shake 纯逻辑 | 不直接读写记忆文件，不实现归档 |
| `AgentSession` | 缩减与续跑调度、预摘要生命周期、记忆入口接线 | 不另建一份与底层不同的预算公式 |
| `SessionManager` | 原始 entry、分支验证、已提交上下文重建 | 不执行历史工具 |
| `MemoryStore` | 有效视图、统一写入约束、快照/水位/幂等提交 | 不自行选择模型或调用任意 provider |
| CLI/RPC/trace | 展示结构化结果及原因 | 不自行推断失败为成功 |

诊断沿用现有 trace，不新增面板：

- 预算：模型、窗口、估算来源、输入量、输出预留、安全余量、判定及缩减前后结果。
- 压缩：来源边界、是否复用预摘要、覆盖范围、实际调用 usage、结束原因。
- 归档：批次 ID、来源 ID、写入/拒绝数量、处理状态及原因码。
- 历史回读：来源 entryId、块位置及返回范围。
- 首次请求即被预算拒绝时，没有 `request/header` 也必须保留并导出该次运行的诊断。
- trace 仍然是 log-only，不能推进会话逻辑叶子或进入 LLM 上下文。
- 新增诊断禁止回显敏感正文；本项不等同于对已有 trace 执行清理。
